# 分阶段详细任务拆解（可直接作为开发看板/Trello/Jira任务）
## 🟢 阶段1：项目初始化 & 工程搭建｜1天
目标：搭建可运行的Vite8+Vue3+TSX工程，目录结构、类型、基础布局就位
1. 初始化 vite 项目，选择 vue-ts，改造支持 TSX
2. 安装全部依赖：three、@types/three、@tweenjs/tween.js、naive-ui、tailwindcss、lil-gui、uuid
3. 配置 vite.config.ts、tsconfig.json，支持jsx/tsx
4. 搭建标准目录结构（和需求文档一致）
5. 新建 `types/index.ts`，录入全部TS类型定义（PartGroup / CarPartItem / ColorScheme / SchemeStorage / ModelConfig / RenderOption / ExportColorJson，与 SRS §5 一致）
6. 编写基础颜色工具函数 `utils/color.ts`（hex ↔ three.Color 互转、HEX 合法性校验）
7. 编写 App.tsx 基础响应式布局（顶部导航 + 左右/上下自适应容器）
8. 新建 `config/partConfig.ts`、`config/modelConfig.ts`、`config/presets.ts` 骨架（部件/模型/预设集中配置，mesh 命名对齐 SRS 附录 A）
9. 放置静态模型资源目录 `assets/model`
   ✅ 验收标准：项目可正常 `dev` 启动，TS无报错，页面布局骨架可见

## 🟢 阶段2：Three三维基础能力封装｜2天
目标：解耦Three场景，封装可复用Hook，完成画布、相机、光照、控制器基础能力
> 开发文件：`hooks/useThreeScene.ts`、`components/MaybachViewer.tsx`
1. 封装 useThreeScene：创建 Scene / PerspectiveCamera / WebGLRenderer（alpha: true，为透明背景/截图预留）
2. 适配容器尺寸、resize监听、devicePixelRatio 适配（clamp 上限 2）
3. 集成 OrbitControls，配置阻尼、旋转缩放限制（min/maxDistance 按包围盒比例推导）、自动旋转（交互时暂停）
4. 搭建光照体系：环境光、主方向光、补光，阴影配置
5. 增加地面网格辅助对象，支持显示/隐藏
6. 背景色、透明背景切换逻辑封装
7. 资源销毁逻辑：组件unmount时，释放renderer、geometry、texture，防止内存泄漏
8. 渲染循环混合策略：交互/动画/自转期间连续渲染，静止后停帧（配合 needsRender 标记）
9. 监听 webglcontextlost / webglcontextrestored，丢失停止循环提示刷新，恢复重建 renderer
10. 集成 Tween 工具，封装相机位置动画函数（支持中止旧动画，供预设视角调用）
11. 开发环境接入 lil-gui 调试面板，生产环境自动移除
   ✅ 验收标准：空白场景可正常渲染，鼠标旋转缩放平移、自动旋转、网格开关、背景色修改生效；静止后无空转 rAF

## 🟢 阶段3：GLB模型加载 + 部件解析 + 材质核心（核心模块）｜2.5天
> 开发文件：`hooks/useCarModel.ts`、`components/LoadingCover.tsx`
1. 引入 GLTFLoader，封装加载方法，支持进度回调（total=0 时走不确定进度）与 30s 超时提示
2. 加载遮罩组件 LoadingCover，展示加载进度、加载失败重试按钮
3. 递归遍历GLB模型scene，按 meshName 精确匹配 + matchPattern 正则匹配 partConfig 配置表
4. 【重点】多实例部件归并：wheel_FL/FR/RL/RR 等命中多个 Mesh 归并为一个逻辑部件，状态联动；未匹配 mesh 开发环境 warn 输出
5. 匹配逻辑：识别可编辑部件、不可编辑部件，读取原始材质 color / metalness / roughness 回填默认值；初始化后默认选中 body
6. 【重点】材质克隆逻辑：修改材质前克隆 Material，杜绝共享材质串色
7. 封装更新部件材质方法：支持单个部件、批量部件统一更新颜色+PBR参数
8. 封装重置方法：重置单个部件、重置全部部件到原始材质
9. 画布点选（FR03-06）：Raycaster 点击选中、Shift 追加、点空白清空、不可编辑部件拦截
10. 选中态 3D 反馈（FR03-07）：OutlinePass 常驻描边（默认通道，移动端降级为 emissive 提亮）+ hover 呼吸高亮复用
11. 模型加载异常捕获、错误抛出
   ✅ 验收标准：GLB成功加载，部件列表自动识别（多实例归并为一行）；点选/勾选双向联动且有视觉反馈；修改颜色实时生效，不存在串色问题；重置功能正常

## 🟢 阶段4：侧边控制面板UI组件开发｜2.5天
> 文件：`components/PartControlPanel.tsx`、`PresetColorGroup.tsx`、`ViewPresetBtn.tsx`
1. 部件分组折叠列表渲染（按 PartGroup：车身组 / 外饰组 / 轮毂组）
2. 部件行：颜色预览块、中文名称、复选框；editable=false时置灰禁用；画布选中时面板行滚动定位高亮
3. 快捷按钮：全选可编辑部件、清空选中
4. 颜色拾色器组件联动：选中部件后激活拾色器，实时改色；多选时显示最后选中部件值并提示「统一应用到 N 个部件」
5. PBR参数滑块：metalness、roughness；支持批量同步
6. 材质快捷预设按钮：亮光车漆 / 哑光车漆 / 金属拉丝
7. 内置预设配色色块组（迈巴赫官方配色），点击批量赋值选中部件（无选中时提示）
8. 预设视角按钮组：正面、45°斜侧、侧面、车尾、俯视、默认视角，带动画切换相机（动画中再次点击立即重启新动画）
9. 渲染设置开关组：自动旋转、网格、阴影、轮廓高亮
10. 撤销 / 重做（FR03-08）：命令栈封装（上限30步），工具栏按钮 + Ctrl+Z / Ctrl+Shift+Z，无可操作时置灰
   ✅ 验收标准：所有UI控件联动三维场景，选中状态、颜色预览和模型保持一致；撤销重做覆盖换色/参数/预设/方案加载操作

## 🟢 阶段5：配色方案管理（本地存储+导入导出）｜1天
> 文件：`hooks/useColorScheme.ts`、`components/SchemeModal.tsx`
1. 封装 localStorage 读写工具，定义存储key（maybach-color-schemes），存储结构含 schemaVersion，仅序列化纯数据字段
2. 弹窗组件：配色方案管理弹窗
3. 保存方案：输入名称，序列化当前所有可编辑部件配置为方案；同名提示「覆盖保存 / 另存为新方案」
4. 方案列表渲染：加载方案、行内重命名、删除方案（二次确认）
5. 导出JSON：生成符合规范的json文件，浏览器下载
6. 导入JSON / 加载方案：文件上传、JSON解析、结构校验（version / parts / HEX 格式 / 数值区间）、部件不存在跳过并告警（覆盖导入与本地加载两条路径）
7. 应用范围语义：预设配色→选中部件；导入/加载方案→全部可编辑部件，UI 文案明示
8. 内置消息提示（NaiveUI Message）
   ✅ 验收标准：刷新页面方案不丢失；导入导出文件可以互相复用；非法文件友好提示不崩溃；换模型后加载旧方案正确跳过缺失部件

## 🟢 阶段6：截图功能与辅助能力｜1天
> 文件：`hooks/useScreenshot.ts`
1. 截图逻辑：preserveDrawingBuffer 或截图前同步 render 一次再读像素（DOM 面板不在 canvas 画面内，无需隐藏）
2. 支持跟随透明背景开关，输出透明PNG（alpha: true；开后处理时走 EffectComposer 输出保留 alpha）
3. 分辨率选项：1x 画布尺寸 / 2x 高清导出（临时放大渲染后恢复）
4. 自动命名截图文件 `maybach-color-yyyymmdd-HHmmss.png`
5. 截图下载触发逻辑
6. 统一消息提示收口：成功、警告、错误文案对齐需求文档 §7
7. 全局联动校验：自动旋转、阴影开关、背景切换联动画布
   ✅ 验收标准：普通与透明背景截图正常无黑屏；2x 导出清晰；开后处理时透明截图 alpha 正确

## 🟢 阶段7：联调、异常处理、移动端适配、性能优化｜1天
1. 全流程联调：从加载、换色、保存方案、切换视角、截图完整走测
2. 移动端触摸交互验证：单指旋转、双指缩放平移
3. 移动端自动降级逻辑：pointer coarse / UA 判定，默认关闭阴影、Outline后处理
4. 性能优化点：
    - 材质更新只在修改事件触发，不每帧遍历
    - 销毁检查：组件销毁，全部three资源释放
    - 大模型加载提示、超时提示、不确定进度兜底
5. 边界case处理：
    - 无部件选中时，禁用拾色器、材质滑块
    - 导入空JSON、损坏JSON
    - 重复保存同名方案
    - 禁用 WebGL 的浏览器出错误提示页（不白屏）
    - 撤销栈打满30步后的丢弃行为
6. BUG修复
   ✅ 验收标准：PC+移动端操作流畅，无内存泄漏，边界场景不会白屏崩溃

## 🟢 阶段8：自测、打包、交付文档｜0.5天
1. 对照SRS文档 §8 测试要点（V1.1 共 15 条）+ 附录 B 设备测试矩阵逐项自测
2. `vite build` 生产打包，检查dist产物（首屏 JS gzip ≤ 500KB、lil-gui 未打入）
3. 本地静态服务器部署dist验证资源路径（避免静态资源404）；确认 GLB 强缓存策略
4. 输出交付说明文档：部署方式、替换模型步骤（引用 SRS 附录 A）、新增车型配置说明
5. 整理已知限制、注意事项（模型规范、车窗材质简化等）

# 📌 独立前置任务（不属于前端工时，需要设计师/3D美术交付）
> 必须在阶段3开发前交付，否则阻塞开发；验收标准以 SRS 附录 A 为准
1. Blender拆分迈巴赫模型，每个可换色部件独立Mesh，按附录 A 命名规范设置 meshName（多实例部件用 _FL/_FR/_RL/_RR 后缀）
2. 材质统一使用 MeshStandardMaterial；同组实例原始参数保持一致
3. 模型减面、glTF-Pipeline压缩导出GLB（≤15MB、≤30万三角、单纹理≤2048）
4. 输出部件对照表（meshName → 中文名称、分组、是否可编辑），双方签字确认
