**文档版本：**V1\.0　　**技术栈：**Vue3 \+ Vite 8 \+ TSX \+ Three\.js　　**文档类型：**前端三维可视化项目需求文档

# 1 引言

## 1\.1 项目背景与目的

面向迈巴赫车型线上可视化预览场景，开发网页端 3D 预览工具。用户可在浏览器中查看整车三维模型，对车身、轮毂、中网、后视镜等各个独立部件自由更换颜色、调整车漆质感，支持保存多套配色方案、截图导出效果图。

**目标：**替代静态图片展示，实现交互式、实时预览车辆定制配色效果。

## 1\.2 项目范围

**本期包含**

- GLB 迈巴赫整车模型加载、三维场景渲染、轨道相机控制

- 部件自动匹配、单选/多选部件实时换色

- 车漆材质参数（金属度、粗糙度）调节

- 配色方案本地存储、导入导出 JSON

- 预设视角动画切换、画布截图下载

- 加载状态、错误提示、基础渲染配置（背景、网格、阴影）

**本期不包含**

- AR 预览、VR 模式

- 车漆珠光、渐变、碳纤维自定义 Shader

- 内饰单独模型切换、零部件拆装动画

- 用户账号、云端存储配色方案（仅本地 LocalStorage）

- 支付、订单、CRM 对接

# 2 总体描述

## 2\.1 用户角色

1. **普通预览用户**：浏览 3D 车辆、修改部件颜色、调整材质、保存配色、截图保存效果图。

2. **运营人员**：导入预设配色 JSON、快速切换多套官方配色模板。

3. **开发人员**：替换模型、新增车型、调整渲染参数、调试性能。

无权限体系，单角色应用。

## 2\.2 运行环境

- PC 端：Chrome ≥110、Edge ≥110、Safari ≥16

- 移动端：现代安卓浏览器、iOS Safari

- 部署方式：静态资源部署（Nginx、OSS、Vercel 等），**无需后端服务**

- 网络：需要加载 GLB 模型资源；支持本地模型资源部署

## 2\.3 产品总体架构

采用 **Vue3 \+ TSX 组件化 \+ 独立 Three Hooks** 分离架构：

- **UI 层**：页面布局、侧边面板、弹窗、按钮、取色器（Vue TSX 组件）

- **三维核心层**：独立 hooks 管理 scene/camera/renderer/controls，和 UI 解耦

- **模型业务层**：useCarModel 负责 GLB 加载、Mesh 遍历、材质克隆、颜色更新

- **数据层**：useColorScheme 管理 localStorage、JSON 导入导出

- **工具层**：颜色转换、截图、Tween 相机动画工具函数

**核心原则：**Three 场景实例与 Vue 组件解耦，组件销毁时自动销毁 three 资源，防止内存泄漏。

## 2\.4 设计约束

1. 模型必须提前拆分独立 Mesh，同一部件不能和其他部件合并；

2. 修改材质时**必须克隆材质实例**，禁止直接修改原始共享材质，否则多部件串色；

3. 大模型资源控制在 15MB 以内，超出需要减面；

4. 所有配色数据保存在浏览器 LocalStorage，清除缓存会丢失方案；

5. 渲染循环按需设计，不做无意义每帧遍历部件；

6. 移动端自动降级：关闭阴影、关闭后处理轮廓，提升帧率。

# 3 功能需求（FR）

## 3\.1 FR01：3D 渲染画布基础模块

### FR01\-01 画布自适应

- 画布跟随父容器尺寸，窗口 resize 自动更新渲染尺寸、相机宽高比；

- 渲染画面保持等比，不拉伸变形；

### FR01\-02 轨道相机控制 OrbitControls

- 右键拖拽：平移画布

- 阻尼平滑开启，交互手感柔和

- 自动旋转开关：开启后模型缓慢自转；**用户鼠标交互时暂停自动旋转**，交互结束恢复

- 触摸适配（移动端）：单指旋转、双指缩放平移

### FR01\-03 光照系统

- 环境光 AmbientLight：提供基础亮度

- 地面网格辅助线开关：网格地板，辅助空间观察

### FR01\-05 加载与异常

- 模型加载阶段展示 Loading 遮罩，展示加载进度（GLTF 加载器 progress）

- 加载成功：关闭遮罩，初始化部件列表

- 加载失败：展示错误提示，支持重试加载按钮

- 加载超时提示

## 3\.2 FR02：模型加载与部件解析模块

### FR02\-01 GLB 模型加载

使用 GLTFLoader 加载指定 GLB 资源，加载完成递归遍历场景内所有 Mesh 对象。

### FR02\-02 部件匹配规则

- 前端内置部件配置数组 partConfig\[\]，每个配置项包含 meshName；

- 遍历 Mesh，严格匹配 mesh\.name === partConfig\.meshName；

- 匹配成功：绑定该 Mesh，纳入可换色部件列表；

- 匹配失败：静默跳过，不纳入控制面板；

- 标记 editable: false 的部件：仅展示，不开放颜色修改（例如车标、玻璃 LOGO 等固定件）。

### FR02\-03 部件初始化

模型加载完成，读取 Mesh 原始材质颜色、metalness、roughness，回填到部件配置；作为该部件初始默认值。

**部件清单（示例，可扩展）：**body 车身、roof 车顶、grille 中网、wheel 轮毂、mirror 后视镜、bumper 保险杠、handle 门把手、trim 饰条、window 车窗。

## 3\.3 FR03：部件选中与单独换色模块

### FR03\-01 部件列表渲染

侧边面板渲染部件列表：

- 展示中文名称、当前颜色预览色块

- 复选框：控制选中状态

- 不可编辑部件：置灰，取色器禁用

- 支持折叠分组（车身组、外饰组、轮毂组）

### FR03\-02 单选 / 多选部件

- 勾选单个部件 → 仅修改该部件材质

- 勾选多个部件 → 批量统一修改颜色、材质参数

- 提供【全选可编辑部件】【清空选中】快捷按钮

### FR03\-03 颜色选择器

- 支持 HEX 颜色输入、可视化拾色面板

- 修改颜色后实时同步到 3D 模型，无刷新

- 输入非法颜色值自动校验、提示

### FR03\-04 部件重置

- 单个部件重置：恢复该部件模型原始材质参数

- 一键全部重置：所有部件恢复模型初始配色

### FR03\-05（可选）部件 Hover 高亮

鼠标 hover 模型 Mesh，通过 OutlinePass 轮廓高亮；同时在侧边面板自动定位并高亮对应部件行。默认关闭，可在设置面板开启，作为高级功能。

## 3\.4 FR04：材质参数调节模块

基于 PBR 材质，调节两个核心参数：

1. Metalness 金属度：0\~1

2. Roughness 粗糙度：0\~1

内置 3 个快捷材质预设按钮：

|材质预设|metalness|roughness|效果|
|---|---|---|---|
|亮光车漆|0\.9|0\.1|高反光镜面|
|哑光车漆|0\.2|0\.8|磨砂质感|
|金属拉丝|0\.95|0\.3|金属颗粒感|

**调节规则：**选中部件生效，多选批量同步参数。

## 3\.5 FR05：预设配色与配色方案管理模块

### FR05\-01 内置预设配色模板

内置多套迈巴赫经典配色：双拼双色、哑光黑、香槟金、银灰等；点击预设，一键覆盖选中部件颜色。

# 4 非功能需求（NFR）

## 4\.1 性能需求

1. 模型加载：15MB GLB 在正常带宽下加载不超过 5s；提供进度反馈

2. 渲染帧率：PC 端稳定 ≥45FPS；移动端 ≥30FPS

3. 换色响应：点击取色器修改颜色，画面更新延迟 \<100ms

4. 内存：组件卸载时，释放 geometry、texture、material、scene、renderer，无内存持续泄漏

5. 限制：禁止每帧循环遍历所有部件，材质更新仅在修改事件触发时执行

## 4\.2 兼容性需求

- PC 主流现代浏览器；不支持 IE

- 移动端触摸交互可用，自动降级阴影、后处理

- 高 DPI 屏幕：renderer 像素比适配 window\.devicePixelRatio，画面清晰

## 4\.3 安全性需求

- 所有资源静态加载，无后端接口；无服务端注入风险

- 导入 JSON 仅在前端解析，不执行脚本，防止注入

- LocalStorage 仅存储配色纯数据，不存储敏感信息

## 4\.4 可扩展性需求

1. **车型扩展**：新增车型只需要替换 GLB 模型 \+ 新增一套 part 部件配置，业务代码无需改动

2. **部件扩展**：新增可换色部件，只需要在 partConfig 数组新增一条配置

3. **材质扩展**：后续增加珠光、渐变材质，可新增材质类型分支，不改动现有换色主流程

## 4\.5 可维护性需求

1. 分层 hooks，三维逻辑和 UI 渲染分离

2. 全部参数、类型使用 TS 强类型定义

3. 关键函数增加注释；模型部件名称集中配置，不写死散落在业务代码

4. 环境区分：开发环境开启 lil\-gui 调试面板、性能统计；生产环境移除

# 10 风险与依赖说明

**最高风险：3D 模型资源**

如果模型没有拆分独立 Mesh，本项目核心换色功能无法实现；交付前必须确认 Blender 导出规范。

- 模型面数过高：会导致卡顿，需要提前减面、压缩 GLB（glTF\-Pipeline）

- 浏览器 GPU 性能差异：低配移动端设备帧率会下降，已经设计自动降级策略

- 纹理资源：GLB 内嵌纹理过大同样会拖慢加载，建议合并压缩纹理
